# Conceptmod 3.1.1

Fresh particle-LoRA trainers now explicitly select ParticleGAN 0.10.0's `empf`
preset, following the owner's EMPF preference. All upstream EMPF hyperparameters
are retained apart from caller-owned task dimensions/budget and explicit
no-weight-EMA settings.

Regularization runs every update: `reg_every=1` resolves to `lazy_k=1` in the
actual EMPF penalty kernel. Explicit recipes requesting skipped regularization
are rejected before trainer construction. Tests compare the complete recipe
with upstream, check actual optimizer-group rates and observe an applied
regularizer on each consecutive update.

The initial generator / critic / particle-bank learning rates are
**0.012 / 0.018 / 0.03**, with the upstream cosine schedule. EMPF uses DualNorm,
zero momentum, smoothing 0.001, `ebi_beta=6`, prior weight 0.01 and the upstream
precision/dense/convolution profiles. Weight EMA and served averaging remain
disabled. [Complete settings](https://github.com/HyperGAN/conceptmod/blob/v3.1.1/docs/particle-lora.md).

```sh
python -m pip install https://github.com/HyperGAN/conceptmod/releases/download/v3.1.1/conceptmod-3.1.1-py3-none-any.whl
```

The same hash-pinned official ParticleGAN 0.10.0 wheel remains available from the
retained 3.1.0 release. Existing saved recipes, weights, original releases and
measured learning-rate results are preserved. A saved incompatible recipe must
use its original runtime; loading does not silently change it to EMPF or rewrite
its regularization interval. No pretrained model or GPU training run is started.
